# Nico-agent

面向求职者的文字版双线 Agent 原型：聊天助手用于讨论岗位、经历和反馈；模拟面试用于独立的逐题练习。两条入口使用不同会话，面试模型上下文只读取当前面试会话与本场明确选择的业务材料，不读取聊天记录。完整消息记录保存在 SQLite；模型每次最多读取最近 16 条消息，并受 32,000 字符的上下文上限约束。

## 启动

需要 Python 3.11+。在此目录执行：

```powershell
python -m pip install -e .
python -m uvicorn career_agent.main:app --reload
```

浏览器打开 `http://127.0.0.1:8000`。默认 `MODEL_PROVIDER=demo`，可以直接体验 1–10 题流程；演示反馈是固定文本，不代表真实评价。

接 OpenAI 兼容的聊天补全接口时，在启动前设置环境变量：

```powershell
$env:MODEL_PROVIDER = "openai_compatible"
$env:MODEL_API_BASE_URL = "https://api.openai.com/v1"
$env:MODEL_API_KEY = "你的密钥"
$env:MODEL_NAME = "提供方的模型名"
python -m uvicorn career_agent.main:app --reload
```

本地数据库默认位于 `data/career_agent.sqlite3`，可用 `DATA_DIR` 指定其他目录。不要将密钥写入项目文件。

## 当前功能

- 聊天与面试分别创建、保存、查询会话；刷新页面后可从历史中恢复。
- 聊天运行中可继续发送补充消息；新消息先保存，旧运行的迟到回复不能覆盖新回复。面试评估中可更正当前题回答，完整记录保留两次输入，报告采用最后一次回答。
- 通用模型循环：构建所属会话上下文、请求模型、并发执行模型请求的只读工具、将结果交回模型，最多 4 轮工具调用。
- Markdown Skill 分别定义聊天与面试行为。工具执行层按入口校验，聊天读取面试报告还要求当前用户消息明确写出目标面试会话 ID；工具只返回题目、反馈和总结，不返回原始回答或证据片段。
- 聊天助手可按需读取已确认经历，以及用户在当前消息明确指定 ID 的材料或面试报告。助手回复可由用户编辑后保存为经历草稿，再到面试准备区确认；草稿不会自动成为面试事实。
- 面试状态为新建、运行中、等待回答、暂停、完成或主动结束。创建时可选择 1–10 题；达到题数后生成总结。回答先落库，模型失败后可继续重试。暂停或结束会使旧运行的迟到结果失效。
- 每题的问题、原始回答、反馈和回答原文证据单独保存；模型提供的证据片段必须能在该题回答中找到，否则本轮不会提交。完成或主动结束后可查看报告，并从有反馈的题目开启独立的单题复练。复练继承原场授权的材料，使用新的问法，报告可对照原题与原反馈。
- 同一会话在运行中拒绝重复提交；不同会话可各自运行。
- 每次模型运行记录入口、模型、耗时、上下文大小、工具名称和结果状态，不在运行事件中复制用户消息；单次运行最多执行 8 个工具调用。
- 可粘贴简历、岗位描述和项目文本，也可从 `.txt`、`.md` 文件导入文本。材料与经历可编辑或撤回；编辑产生新记录，旧面试仍使用原版本。经历主张先存为草稿，由用户确认后才能选入面试。创建面试时显式勾选材料与已确认经历，面试工具只能读取本场选中的资源。

实现参考了 nanobot 的上下文构建与工具注册、Akashic Agent 的会话状态提交约束，以及 Pi 的模型调用边界与工具循环。当前只保留求职场景需要的部分。

## 当前边界

这是本地单用户原型，尚无登录和租户授权；文本导入不支持 PDF、DOCX 或音频解析。用户确认经历不等于独立事实核验，回答证据的原文匹配也不等于反馈事实正确。真实模型效果尚未验证。多用户上线前必须补身份与资源授权。语音、实时转写、多渠道、日程、外部搜索和更多 Provider 属于后续阶段。
