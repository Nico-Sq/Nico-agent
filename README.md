# Nico-agent

面向求职者的文字版双线 Agent 原型：聊天助手用于讨论岗位、经历和反馈；模拟面试用于独立的逐题练习。两条入口使用不同会话，面试模型上下文只读取当前面试会话与本场明确选择的业务材料，不读取聊天记录。完整消息记录保存在 SQLite；模型每次最多读取最近 16 条消息，初始上下文最多 32,000 字符，加入工具结果后的模型输入最多 64,000 字符。

## 启动

需要 Python 3.11+。在此目录执行：

```powershell
python -m pip install -e .
python -m career_agent
```

浏览器打开 `http://127.0.0.1:8000`。该命令只监听本机回环地址；开发时需要自动重载可运行 `python -m uvicorn career_agent.main:app --reload`。默认 `MODEL_PROVIDER=demo`，可以直接体验 1–10 题流程；演示聊天只回显输入的前 1000 字，演示反馈是固定文本，不代表真实评价。

接 OpenAI 兼容的聊天补全接口时，在启动前设置环境变量。请求使用 `max_tokens=2048`；所选端点需要支持该参数和工具调用协议：

真实模型模式会将本次聊天消息、面试回答及获授权读取的材料发送到配置的模型服务。请先确认该服务符合你的数据使用要求。

```powershell
$env:MODEL_PROVIDER = "openai_compatible"
$env:MODEL_API_BASE_URL = "https://api.openai.com/v1"
$env:MODEL_API_KEY = "你的密钥"
$env:MODEL_NAME = "提供方的模型名"
python -m career_agent
```

真实模型模式至少要设置 `MODEL_NAME`，`MODEL_API_BASE_URL` 要是有效的 HTTP(S) 地址；本机兼容服务若不要求认证，`MODEL_API_KEY` 可以不设置。配置不完整时页面会显示原因，并暂时禁用聊天发送和开始面试；修改环境变量后重启应用。兼容接口若报告输出截断或其他非正常结束，本轮不会采纳回复或执行其中的工具调用；已提交的聊天消息或面试回答会保留，调整请求后可重试。

本地数据库默认位于 `data/career_agent.sqlite3`，可用 `DATA_DIR` 指定其他目录。启动时会为已有数据库自动增加运行认领字段，保留原会话；升级前可先下载业务数据快照。不要将密钥写入项目文件。

恢复页面下载的业务数据时，先停止应用，再运行：

```powershell
python -m career_agent.restore .\nico-agent-backup.sqlite3
```

命令会校验备份、在目标目录生成临时数据库并校验，再把现有业务库另存为 `career_agent.before-restore-<ID>.sqlite3`，最后替换目标文件。使用了 `DATA_DIR` 时，恢复命令也要设置相同变量；账户模式需用 `--target` 指向对应账户的 `data/users/<用户ID>/career_agent.sqlite3`。下载的业务快照不含 `auth.sqlite3` 中的账户凭据。

应用启动时、运行期间每小时及正常退出时检查本地业务库。在各数据库旁的 `backups/` 目录保留最近 7 份按 UTC 日期命名的每日 SQLite 快照，并在每次检查时原子更新 `career_agent-latest.sqlite3`。每日快照保存当天首次检查时的数据；`latest` 保存最近一次检查时的数据。账户模式按账户分别备份业务数据；自动快照同样不含账户凭据。恢复自动快照时也使用上面的命令，并将快照路径作为第一个参数。异常断电时仍可能丢失最近一次检查之后的改动。

需要账户隔离时，在启动前设置 `$env:AUTH_REQUIRED = "true"`。首次打开页面可注册账户；同一账户连续 5 次登录失败后，15 分钟内的登录会返回 429。登录凭据保存在 `data/auth.sqlite3`，每个账户的业务数据保存在 `data/users/<用户ID>/career_agent.sqlite3`。原来的本地单用户数据不会自动迁入账户目录。

## 当前功能

- 页面侧栏以“新对话”和“AI 面试”为两个入口；点击“新对话”打开空白草稿，历史记录仍可查找并恢复。新对话主区提供常用问题草稿、材料引用与当前对话备注，发送前仍由用户确认文字。AI 面试的准备、答题与报告流程保持独立。
- 页面配色仅使用黑、白、灰；选中、焦点和提示状态通过灰阶、边框和文字区分。
- 聊天与面试分别创建、保存、查询会话；刷新页面后可从历史中恢复。
- 两种会话都可手动命名或清空名称恢复默认显示，侧栏可按名称、目标、对话内容或 ID 查找；面试还能按题目、回答和反馈查找。搜索在当前入口和当前账户的业务库内执行，列表响应不包含消息正文或聊天固定备注。名称只用于展示，不进入模型上下文，也不会中断正在运行的会话。
- 聊天页可直接选择现有材料或已形成反馈的面试报告，先将引用 ID 加入消息草稿，用户检查并发送后才授权本轮工具读取；仍可手动输入 ID。
- 每个聊天会话可保存最多 2000 字的固定备注，后续消息即使超出最近 16 条上下文窗口仍能使用；备注不会进入面试模型上下文，清空并保存即可删除。编辑备注会使该聊天旧版本的运行失效。
- 可选账户模式提供注册、登录、退出和按账户独立的数据文件；退出后页面会清空当前账户的消息、材料列表及未发送草稿。默认仍为本地单用户模式。页面可下载当前用户的 SQLite 业务数据快照。
- 聊天运行中可继续发送补充消息；新消息先保存，旧运行的迟到回复不能覆盖新回复。面试评估中可更正当前题回答，完整记录保留两次输入，报告采用最后一次回答。
- 聊天请求失败或中断后，若最后一条仍是未回复的用户消息，可直接重试，不需要再保存一条重复输入。
- 通用模型循环：构建所属会话上下文、请求模型、并发执行模型请求的只读工具、将结果交回模型，最多 4 轮工具调用。
- Markdown Skill 分别定义聊天与面试行为。工具执行层按入口校验，聊天读取面试报告还要求当前用户消息明确写出目标面试会话 ID；工具只返回题目、反馈和总结，不返回原始回答或证据片段。
- 聊天助手可按需分批读取已确认经历（每次最多 20 条，可按关键词查找并继续读取），以及用户在当前消息明确指定 ID 的材料或面试报告。助手回复可由用户编辑后保存为经历草稿，再到面试准备区确认；草稿不会自动成为面试事实。
- 面试状态为新建、运行中、等待回答、暂停、完成或主动结束。创建时可选择 1–10 题；达到题数后生成总结。可以跳过当前题，跳题事件和题号会保存，跳过的题目不产生回答反馈或证据。回答先落库，模型失败后可继续重试。暂停或结束会使旧运行的迟到结果失效。
- 每题的问题、原始回答、反馈和回答原文证据单独保存；模型提供的证据片段必须能在该题回答中找到，否则本轮不会提交。完成或主动结束后可查看报告，并从有反馈的题目开启独立的单题复练。复练继承原场授权的材料，使用新的问法，报告可对照原题与原反馈。
- 面试模型输出必须与当前题数阶段一致：首题不能带反馈或总结，结束前不能提前总结，最后一题不能再出题；题目、反馈、总结和证据数量受长度上限约束。完整的 JSON 代码围栏可被解析，内部仍须满足同一结构校验。聊天与面试单次模型输出最多 12,000 字符，异常输出保留已保存的用户输入供重试。
- 长面试的模型上下文额外包含各已完成题目的简短问题、反馈和回答原文证据，供全场总结参考；完整回答仍保存在 SQLite，不因上下文裁切而改写。
- 同一面试题的更正会使旧运行失效；聊天补充输入会使旧回复失效。运行时在每轮请求前后检查版本，聊天工具不能借用新消息的资源授权。同一会话版本只允许一个请求调用模型，重复请求返回 `in_progress` 或 `interrupted`，不同会话可各自运行。进程异常退出后如会话仍为运行中，可通过聊天中断或面试暂停、恢复继续。
- 每次模型循环最多 4 轮、8 个工具调用，最长 120 秒；模型报告的累计 token 达到 16,000 后不再继续工具循环。每轮遇到 429 或 503 最多重试一次，超时及连接中断不自动重试，避免不确定请求重复计费。
- 每次模型运行记录入口、模型、提示词版本、耗时、上下文大小、工具名称、结果状态及模型实际返回的 token 用量，不在运行事件中复制用户消息。端点未返回用量时标记为 `unavailable`，字符预算和 token 阈值均不等于人民币或美元费用上限。模型错误响应只返回稳定错误码和简短说明，不回传上游原始报错。
- 聊天和面试会话内可展开最近 30 条模型与工具运行记录，查看运行状态、耗时、请求数、令牌用量覆盖情况、工具结果和错误码；用量来自模型服务实际返回的数据，演示模式或未返回用量的接口会显示不可用。
- 页面在模型配置不完整时直接提示缺项；输入框与后端长度上限保持一致，服务器校验错误会提示检查必填项、长度和格式。兼容接口报告输出截断时，不提交不完整的回答或执行不完整的工具调用。
- 可粘贴简历、岗位描述和项目文本，也可从 `.txt`、`.md`（UTF-8、GB18030）、`.docx` 和文本型 `.pdf` 提取内容，检查后再保存。单文件最多 5 MB、20 页 PDF、提取文本最多 4000 字符。材料与经历可编辑或撤回；编辑产生新记录，旧面试仍使用原版本。经历主张先存为草稿，由用户确认后才能选入面试。创建面试时显式勾选材料与已确认经历，面试工具只能读取本场选中的资源。
- 可从报告显式跳转到聊天讨论反馈；聊天与面试记录可分别导出为 Markdown。会话可删除，删除面试时会清理其派生复练。

实现参考了 nanobot 的上下文构建与工具注册、Akashic Agent 的会话状态提交约束，以及 Pi 的模型调用边界与工具循环。当前只保留求职场景需要的部分。

## 当前边界

账户模式提供基本的数据隔离和按账户登录失败限流，尚无密码重置流程，不应直接作为公网生产服务。扫描版 PDF 没有文本层时需先进行 OCR；目前不解析音频。聊天固定备注需由用户维护，不会自动从历史对话提取。用户确认经历不等于独立事实核验，回答证据的原文匹配也不等于反馈事实正确。真实模型效果尚未验证。兼容端点不返回 token 用量时无法强制执行累计 token 阈值；真实货币费用上限需要模型价格和计费数据。语音、实时转写、多渠道、日程、外部搜索和更多 Provider 属于后续阶段。
